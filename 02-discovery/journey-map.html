Future-state journey: The Fleet Dispatcher

RouteLogic Velocity · Module 2 journey map

GoalGet route changes to drivers right away and see accurate stop status, so the operation runs from one source of truth.
Today's workaroundA WhatsApp group the team calls "the real system" (UXR-02), plus phone calls and manual board reconciliation.
StrategyReclaim operational simplicity by stripping away legacy noise and making the tool the fastest option for everyday work.

Timeline

Stages

  1. Reassign the route

    User action
    Drags stops to a new driver on the board → change is saved in one step.
    Internal state
    Confident the board is the only place to make the change.
    Pain point addressed
    Retyping changes into WhatsApp → one entry, no copy errors.

  2. Driver notified

    User action
    Sees a "received by driver" check within seconds → no follow-up calls.
    Internal state
    Reassured the driver will turn before going the wrong way.
    Pain point addressed
    8–15 min delay, no push (BUG-2044) → instant push notification.

  3. Live stop status

    User action
    Glances at the board for stop status → answers customers immediately.
    Internal state
    Trusts the board again ("in progress" really means in progress).
    Pain point addressed
    20–60 min status lag (BUG-2072) → status updates in near real time.

  4. Close the day

    User action
    Reviews completed stops on the board → no reconciling against chat threads.
    Internal state
    In control; the WhatsApp group goes quiet.
    Pain point addressed
    Manual reconciliation and report gaps → complete, timestamped delivery record.

Competitive advantages over the manual workaround

  1. Enter once, reach everyone → one change updates both the driver and the board.
  2. Structured, timestamped record → feeds the reporting enterprises bought, which WhatsApp can't provide.
  3. Scales safely → push alerts replace chat-reading while driving, whatever the fleet size.

Evidence: UXR-02, UXR-09, BUG-2044, BUG-2072. The "received by driver" check and "within seconds" timing are design targets, not research findings.
